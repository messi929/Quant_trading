## 3. Phase별 상세

### Phase 1 (5/15~6/14, 4주) — Diagnostics First

**목표**: 측정 인프라 구축. 거래 결정 무영향. paper 동시 활성화 가능.

**작업** (병렬 가능):

```
PR-1.1  No-Trade Reason Logger        (1주, 5d work)
        - v3/strategy/diagnostics.py 신규
        - RejectReason enum
        - NoTradeLog dataclass
        - 기존 recommendation_log.jsonl 통합·deprecate
        - SignalGenerator hook 추가 (read-only)

PR-1.2  Transfer Coefficient Monitor  (3일)
        - diagnostics.py 같은 파일에 통합
        - daily TC 계산 + alert
        - feature flag: tc_monitor

PR-1.3  Execution Quality Monitor     (3일)
        - v3/execution/execution_quality.py 신규
        - PaperBroker 체결가 + 의도가 비교
        - bps 단위 슬리피지 기록

PR-1.4  build_edge_dataset.py         (1.5주, research)
        - v3/research/build_edge_dataset.py 신규
        - 5년 backtest replay (2021-01 ~ 2026-04)
        - panel 25,000+ row 생성
        - lookahead 검증 + survivorship 처리

PR-1.5  Test infrastructure            (3일)
        - test_diagnostics.py
        - test_no_trade_logger.py
        - test_execution_quality.py
        - 회귀 테스트 hook 검증
```

**합격 기준**:
- [ ] 매일 `no_trade_log_YYYY-MM-DD.jsonl` 생성, 모든 후보 reject reason 부여
- [ ] TC가 매일 계산되어 `tc_history.jsonl` 누적
- [ ] paper 1주 운영 중 production 결정 무변경 (parity 확인)
- [ ] `data/research/edge_dataset_2026-06.parquet` 생성, panel size ≥ 20,000
- [ ] panel sanity check: regime 분포, sector 분포, 결측값 < 5%

### Phase 2 (6/15~7/15, 4주) — Calibration & Edge Engine

**목표**: raw_opportunity → expected_return → net_edge 변환 layer 구축.

**작업** (순차):

```
PR-2.1  EdgeCalibrator                 (1주)
        - v3/strategy/edge_calibrator.py 신규
        - calibration table 빌드 (calibrate_edge.py)
        - fallback chain (decile / decile×regime / global)
        - validate_edge.py (OOS 검증)

PR-2.2  EdgeEngine                     (1주)
        - v3/strategy/edge_engine.py 신규
        - cost_model 분해 (commission/spread/impact/slippage)
        - downside risk penalty
        - net_edge 산출

PR-2.3  Edge Tier System               (1주)
        - v3/strategy/edge_tier.py 신규
        - 분위수 기반 임계값 도출
        - tier별 sizing multiplier

PR-2.4  BookOptimizer 골격             (1주)
        - v3/strategy/book_optimizer.py 신규
        - SignalGenerator wrap
        - feature flag 통합
        - backtest engine + live pipeline에서 BookOptimizer 호출
        - 초기 모든 Edge feature OFF (V3.2.1 동작 보존)
```

**합격 기준**:
- [ ] Calibration OOS: top decile forward return > bottom decile (단조)
- [ ] Calibration OOS: top decile net return > cost (수익 가능성 확인)
- [ ] EdgeEngine entry threshold가 분위수에서 도출됨 (hardcoded 0.0040 미사용)
- [ ] Edge Tier S/A/B/C 분류가 OOS에서 realized return 단조성 확인
- [ ] BookOptimizer feature flag 모두 OFF 시 V3.2.1과 backtest 결과 100% 일치

### Phase 3 (7/16~8/15, 4주) — Exit Policies

**목표**: Winner 보호 + 시간 기반 trigger를 thesis 재평가로 격상.

**작업** (일부 병렬):

```
PR-3.1  Conditional Veto 정상화        (1주) — FOLLOW_UPS 1순위

PR-3.3  Signal Decay                   (3일)
```

### 4.2 일정 buffer

각 Phase 일정에 **20% buffer** 포함 (디버깅, 회귀 hook 실패 대응, 사용자 검토 시간).

위험 항목:
- Phase 1의 `build_edge_dataset.py`: 5년 backtest replay 시간 미지수 → 1주 buffer
- Phase 2의 OOS validation: 단조성 미달 시 alpha/feature 추가 작업 (별도 알파 phase 필요할 수도)
- Phase 4의 Allocation: VolTargetSizer 통합 까다로움 → 0.5주 buffer

## 6. 위험 관리

### 6.1 일정 위험

- **Phase 2 OOS 단조성 미달**: 가장 큰 risk. 이 경우 새 알파 추가가 prerequisite → Phase 2 연장 4~8주
- **Calibration panel 표본 부족**: 5년에서도 부족하면 7년으로 확장. COVID 2020 효과 제거 작업 추가
- **Phase 4 sizing 불안정**: VolTargetSizer 통합 어려우면 AllocationEngine을 sizer 대체로 변경

### 6.2 품질 위험

- **회귀 hook 실패 누적**: 매 PR마다 `v3/tests/test_regression.py` 통과 필수 (CLAUDE.md 정책)
- **Live-Backtest parity 깨짐**: PR-2.4 BookOptimizer 통합 시 가장 위험한 시점 → 별도 parity test 추가
- **paper 검증 데이터 손상**: feature flag OFF 상태라도 생성된 BookAction이 실제 trade에 영향 없는지 monitor

### 6.3 paper promotion 위험

- **악화 시 자동 rollback**: 각 정책 paper 활성화 후 1주 PnL이 baseline 대비 -2% 악화 시 즉시 flag OFF
- **검증 진행 중 변경 금지**: 매 promotion 후 1주는 다른 정책 변경 없음 (FOLLOW_UPS 철칙)
