V3.3 Profitability Engine 단일 운영 reference.

- **무엇이 바뀌었나** — V3.2.1 vs V3.3 정책 차이
- **언제 다시 손대나** — 변경 의사결정 트리거 + 절차
- **어떻게 모니터링하나** — 일/주/월 단위 점검 루틴
- **어떻게 롤백하나** — 단계별 절차

> ⚠️ 2026-05-13 update — V3.3 부분 활성 상태:
>
> | Phase | Features | 상태 |
> |-------|----------|:-:|
> | Phase 1 diagnostics | `no_trade_logger / tc_monitor / execution_quality` | ON |
> | Phase 2 Edge layer | `edge_calibrator / edge_engine / edge_tier / allocation` | **OFF** |
> | Phase 3 exit policies | `exit_thesis / partial_exit / signal_decay` | ON |
> | Phase 4 capital | `pyramid / rotation` | **OFF** |

> `max_gross_exposure`, ABNB 자본 38% 실증), `flush_diagnostics` try/finally

## 1. 변경된 정책 (V3.2.1 → V3.3 부분 활성)

### 1.1 진입 (Entry)

| 항목 | V3.2.1 | V3.3 부분 활성 (2026-05-13~) | V3.3 전체 활성 (Edge ON, 보류 중) |
|------|--------|------------------------------|----------------------------------|
| 알파 게이트 | `opportunity > cost × 1.75` | 동일 (게이트 불변) | 동일 |
| DirectionalAlpha | `trend / reversion` | **`trend / reversion / volume_surprise`** (5/13 promoted) | 동일 |
| `ic_to_weights` | `max(IC − 0.02, 0)` → normalize | **`sqrt(shrunk) + min_weight=0.10` floor** (winner-take-most 완화) | 동일 |
| `position_scale` 의미 | 종목당 곱셈 (`raw_weight × scale`) | **포트폴리오 `max_gross_exposure` 한도** (V3.3 RegimeBudget과 정합) | 동일 |
| 사이저 floor | `sizer.min_weight = 0.15` (Phase 25.2) | 동일 + 곱셈 무력화 해제 (5/13) | 동일 |
| `predicted_vol` source | `vol_scores['vol_score']` (잘못 매핑) | **`ohlcv['vol_cc_20d']`** annualized (5/13 fix) | 동일 |
| Edge tier 분류 | 없음 | 없음 (Phase 2 OFF) | S/A/B/C 분류 (calibration 활성 시) |
| Pyramid (winner add-on) | 없음 | 없음 (Phase 4 OFF) | 활성 (winner-only invariant) |
| 월 회전 cap | unique-ticker 5회 (Phase 25.1) | 동일 | 동일 + V3.3 rotation 별도 cap |

### 1.2 청산 (Exit)

| 트리거 | V3.2.1 | V3.3 부분 활성 (현재) |
|--------|--------|------------------------|
| `portfolio_stop` (-1.0~2.0%) | 무조건 EXIT | 동일 (risk_exit branch) |
| `vol_contraction` (≤70% × 3일) | 무조건 EXIT | 동일 (risk_exit branch) |
| `dynamic_stop_mae` | 무조건 EXIT | 동일 (risk_exit branch) |
| `profit_take` (Day1 +5% → Day5 +1.5%) | inline veto (8h stale 단순 drop) | **ExitThesis 16h staleness + signal_refresh + replacement_edge** (Phase 3 ON) |
| `max_hold` (5일) | inline veto 동일 | 동일 (16h fix 적용) |

**핵심 차이**: profit_take/max_hold 발동 시 V3.2.1은 8h 초과 시 unconditional
fire (4/21 ADI +9.02% 자르기 사례), V3.3 Phase 3은 16h staleness +
ExitThesisEngine.decide() 분기 (HOLD/REDUCE/ROTATE/EXIT).

### 1.3 V3.3 신규 정책 활성/비활성 상태

| 정책 | 설명 | 트리거 조건 | **2026-05-13 상태** |
|------|------|-------------|--------------------|
| **HOLD (conditional veto)** | profit_take/max_hold 발동 BUT residual_edge > 0 → 유지 | residual_edge > `hold_min_residual_edge=0.0` | **ON** (Phase 3) |
| **TRIM (partial exit)** | residual_edge 약화 → 30% 청산 + 70% 유지 | residual < `reduce_zone_edge=0.0015` | **ON** (Phase 3) |
| **ROTATE (capital rotation)** | 다른 종목 net_edge 가 더 강하면 교체 | improvement > switching_cost + `rotation_margin=0.0025` | **OFF** (Phase 4, Edge 의존) |
| **ADD_TO_WINNER (pyramid)** | 보유 winner 에 weight 추가 | `pyramid_winner_only` invariant 통과 | **OFF** (Phase 4, Edge 의존) |
| **AllocationEngine sizing** | net_edge / risk 기반 weight override | features.allocation ON + Edge layer 활성 | **OFF** (Phase 2) |
| **Diagnostics flush** | 매 세션 끝 buffer → disk (no_trade_logs 등) | run_session try/finally | **ON** (5/13 추가, Phase 1) |

## 2. 변경 의사결정 트리거 (When to Touch Again)

V3.3 활성화 이후 **새 코드 추가는 아래 트리거 중 하나가 발생할 때만**.

### 2.1 자동 트리거 (운영자 개입 불필요)

| 트리거 | 시점 | 자동 처리 |
|--------|------|----------|
| `v33-rollback-check.timer` | 매일 16:30 KST | 1주 PnL ≤ -2% 시 features 자동 OFF, 알림 (`/var/log/v33-rollback.log`) |
| `calibration-retrain.timer` | 매월 1일 07:00 KST | build → calibrate → validate. PASS 시 자동 publish, FAIL 시 기존 유지 |
| `alpha-retrain.timer` | 매월 1일 06:00 KST | regime alpha 가중치 재학습. 자동 적용 |
| `v33-daily-report.timer` | 매일 16:00 KST | `research/reports/daily/YYYY-MM-DD.md` 생성 (관찰만) |

### 2.2 수동 트리거 (운영자 판단 필요)

| 시나리오 | 점검 시점 | 판정 기준 | 조치 |
|----------|-----------|-----------|------|
| **6/1 Calibration 결과** | 6월 첫 주 | validation_2026-06.md PASS/FAIL | PASS → 자동 publish 확인. FAIL → 7/1 재시도 대기 또는 Sec 4 알파 재설계 |
| **5/24 페르소나 점수** | 1~2주 paper 후 | recommendation_log.jsonl + paper_account.json | 원칙 1·2 점수 baseline (5/3) 대비 변화 |
| **자동 rollback 발동** | 즉시 (매일 16:30) | `/var/log/v33-rollback.log` 에 trigger=True | 원인 분석 → 해당 feature 영구 OFF 또는 fix |
| **Validation 연속 FAIL** | 7월 / 8월 calibration | top-bottom 음수 반복 | 알파 자체 재설계 (V3.4) |
| **Live 버그 발견** | 즉시 | error log / paper trade 결과 | 회귀 테스트 추가 후 fix |
| **Persona 점수 악화** | 4주 누적 | 원칙 점수 baseline 미달 | 원인별 feature OFF |

### 2.3 절대 금지

- **임의 튜닝** ("느낌으로" hold_min_residual_edge 조정 등) — 데이터 없이 정책 건드리면 백테스트-라이브 parity 깨짐
- **동시 다발 수정** — 한 번에 한 가지 변경, 1~2주 검증, 다음
- **Validation FAIL 무시 후 게이트 완화** — V2.2 교훈 (게이트 완화 → -6.91%)
- **invariant 우회** — `pyramid_winner_only` / `risk_exit_never_vetoed` / `LEVERAGE_CAP` 절대 비활성 금지
- **`pytest.skip` / hook 우회** (`--no-verify`) — 사용자 명시 지시 없이 금지
