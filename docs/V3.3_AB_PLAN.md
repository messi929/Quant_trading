# V3.3 Profitability Engine — Backtest Ablation Plan

**기반**: `docs/V3.3_DESIGN.md`, `docs/V3.3_ROADMAP.md`, `docs/V3.3_INTERFACES.md`
**역할**: A1~A9 + Full ablation 실험의 데이터셋·실험 절차·측정·합격 기준 명세.
**시점**: Phase 5 (2026-09-16~) 또는 각 Phase 종료 시 부분 ablation.

---

## 1. 실험 목적

3가지 질문에 답한다:

```
Q1. 9개 정책 + 4개 베이스 모듈 각각이 실제로 수익률에 기여하는가?
Q2. 정책 간 상호작용 — 두 정책을 동시 켤 때 emergent 효과가 있는가?
Q3. 통합(Full) 결과가 V3.2.1 baseline 대비 페르소나 원칙 2 "크게"를 처방하는가?
```

**핵심**: 각 정책은 자기 책임 영역에서만 효과를 입증해야 한다.
- Conditional Veto → average_win 증가
- Pyramid → average_deployed_capital 증가
- Edge Tier → tier별 realized return monotonicity

이를 만족 못하면 그 정책은 paper에 promote 안 된다 (Roadmap §5.4 합격 기준).

## 2. 데이터셋 정의

### 2.1 Calibration Panel

`v3/research/build_edge_dataset.py` 출력:

```
경로:        data/research/edge_dataset_2026-06.parquet
기간:        2021-01-01 ~ 2026-04-30 (5.3년)
Universe:    NASDAQ-100 (시점별 historical constituents — survivorship 처리)
예상 size:   ~25,000 row (99 ticker × ~250 trading day/year × 5.3 year × ~20% sampling)
```

### 2.2 Train/Test Split

**1차 split (calibration 학습용)**:
```
Train:    2021-01-01 ~ 2025-04-30 (4.3년, 약 80%)
OOS Test: 2025-05-01 ~ 2026-04-30 (1년, 약 20%)
```

**2차 split (ablation backtest)**:
- Calibration table은 Train에서만 학습.
- Ablation backtest는 OOS Test 1년에 대해 실행.
- 추가로 walk-forward 검증 (선택적): Test 1년을 4분기로 나눠 fold마다 calibration 재학습.

**가드**:
- Lookahead 금지: t 시점 calibration은 [t-5y, t]만 사용.
- Survivorship: 각 t에서 그 시점 listed ticker만 포함.
- 결측 처리: vol_score 결측 시 제외 (panel 구성 단계).

### 2.3 Regime 분포 확인 (sample size 검증)

OOS 1년 panel의 regime 분포가 train과 유사해야 한다:

```
strong_bull:  >= 100 row    (없으면 OOS 검증 불가)
bull:         >= 500 row
neutral:      >= 1000 row
caution:      >= 500 row
bear:         >= 100 row
```

미달 시 OOS 기간 확장 또는 cross-fold 재구성.

## 4. 실험 매트릭스 — A1 ~ A9 + Full

각 실험은 baseline 위에 누적 add (cumulative) — "policy B는 policy A의 효과 위에 measure".

### 4.1 정의 표

| 실험 | 추가 feature flag | 측정 책임 영역 |
|------|------------------|---------------|
| **Base** | (all OFF) | V3.2.1 reproduction |
| **A1** | Base + `edge_calibrator` | calibration 자체의 noise reduction |
| **A2** | A1 + `edge_engine` | net_edge gate (cost + risk 분해) |
| **A3** | A2 + `edge_tier` | tier별 realized return monotonicity |
| **A4** | A3 + `conditional_veto` | winner 조기 청산 감소 (FOLLOW_UPS 1순위) |
| **A5** | A4 + `exit_thesis` | thesis 재평가 종합 효과 |
| **A6** | A5 + `signal_decay` + `partial_exit` | 정교한 exit (alpha별 + 부분) |
| **A7** | A6 + `allocation` | net-edge sizing의 capital efficiency |
| **A8** | A7 + `pyramid` | winner expansion → "크게" 처방 |
| **A9** | A8 + `rotation` | capital rotation의 추가 efficiency |
| **Full** | (all ON, 진단 포함) | 통합 효과 |
| **Full-NoDiag** | Full minus 진단 3개 | 진단 overhead 측정 |

### 4.2 추가 비교 실험 (선택적)

각 정책의 **단독 효과** 측정 (cumulative 아닌 isolated):

| 실험 | feature flag |
|------|-------------|
| **I-CV** | Base + `conditional_veto` only | 단독 효과 |
| **I-PY** | Base + `edge_calibrator` + `edge_engine` + `pyramid` only | pyramid 단독 |

## 6. 합격 기준

### 6.1 정책별 합격 기준

각 정책이 자기 책임 영역에서 의미 있는 개선을 보여야 한다:

| 실험 | 합격 기준 |
|------|----------|
| A1 (Calibrator) | OOS top decile forward return > bottom decile (단조성 Spearman > 0.5) |
| A2 (EdgeEngine) | net_edge entry threshold가 hardcoded 아닌 분위수 도출. top decile net return > cost. |
| A3 (Tier) | S/A/B/C 순서로 realized return 단조 (Spearman > 0.6) |
| A4 (Conditional Veto) | profit_take 후 5d forward return > 0인 경우 빈도 상승. average_win 5%+ 증가. |
| A5 (ExitThesis) | A4 + thesis_break 청산 vs 시간 청산 분리. realized_return per trade 개선. |
| A6 (Decay+Partial) | average_holding_days alpha별로 차등 (trend > reversion). MDD 악화 없음. |
| A7 (Allocation) | average_deployed_capital +5%p 이상. TC > 0.30. |
| A8 (Pyramid) | winner add-on success rate > 55%. 손실 포지션 add-on 0건. |
| A9 (Rotation) | rotation_success_rate > 55%. switching cost를 초과한 net improvement 양수. |
| Full | 아래 §6.2 |

### 6.2 Full 실험 합격 기준

| 측정 | V3.2.1 baseline | V3.3 Full 목표 | 거부 기준 |
|------|----------------|--------------|----------|
| Sharpe | 1.65 (BT) | ≥ 1.50 | < 1.30 |
| MDD | 4% (BT) | ≤ 8% | > 12% |
| Profit Factor | 3.93 (BT) | ≥ 2.0 | < 1.5 |
| CAGR | ~38% (BT) | ≥ 25% | < 15% |
| Win Rate | 64% (BT) | ≥ 55% | < 50% |
| Avg Deployed | ~60% (BT) | ≥ 75% | < 55% |
| TC | (미측정) | ≥ 0.30 | < 0.10 |
| Tier Monotonicity | n/a | Spearman > 0.5 | < 0.2 |
| Forbidden ops | 0 | 0 | leverage > 1.00, 손실 add-on, risk veto 1건이라도 |

**거부 기준 1건이라도 위반 → V3.3 Full 활성화 보류, 원인 분석 후 재실험**.

### 6.3 합격 기준의 statistical significance

단일 1년 OOS는 표본 부족 가능성. 추가 검증:

```
Bootstrap resampling (B=1000):
  - 거래 단위 resampling으로 Sharpe 95% CI
  - V3.2.1 vs V3.3 Full Sharpe 차이 paired bootstrap p-value
  - p < 0.10 (보수적 기준 — 1년 데이터로 0.05는 어려움)

Walk-forward (4 folds):
  - 각 fold에서 동일 metric 측정
  - 4 fold 모두에서 V3.3 ≥ V3.2.1 → 강한 신호
  - 3/4 → 중간 신호
  - ≤ 2/4 → 의심스러움 (재실험)
```

## 7. 정책 간 상호작용 분석

### 7.1 가설 — 어떤 조합이 emergent 효과를 보일까?

```
H1.  Conditional Veto + Pyramid:
       winner 보호된 후에 add-on 가능 → average_win 추가 상승
       (단독 Pyramid보다 H1 조합이 add-on success rate 더 높을 것)

H2.  Edge Tier + Allocation:
       S-tier에 더 큰 weight 배분 → top decile capture 상승
       (Tier 없이 Allocation은 net_edge 단순 비례 sizing)

H3.  Signal Decay + ExitThesis:
       trend는 길게, reversion은 짧게 → average_holding_days alpha-specific
       (단독 ExitThesis는 모든 alpha 동일 처리)

H4.  Rotation + Pyramid (충돌 가능):
       Rotation은 capital을 새 ticker로 이동, Pyramid는 기존 winner에 add
       두 정책 동시 켜질 때 어떤 우선순위? action_priority가 결정.
```

### 7.2 검증 방법

```
A4 (Veto only) vs A8 (Veto + Pyramid):
  add-on success rate 비교 → H1 검증

A2 (EdgeEngine only) vs A7 (EdgeEngine + Tier + Allocation):
  top_decile_capture 비교 → H2 검증

A5 (ExitThesis only) vs A6 (ExitThesis + Decay + Partial):
  alpha별 holding days 분리 → H3 검증

A8 (...+ Pyramid) vs A9 (...+ Rotation):
  conflict 빈도 측정 → H4 우선순위 검증
```

## 8. Tier별 / Regime별 분석

### 8.1 Tier별 Realized Return 단조성 (A3 합격 기준)

```
출력 예시:
Tier   |  N    | Mean Return |  Win Rate | PF    | Avg Hold
S      |  120  | +1.85%      |  68%      | 4.2   | 6.8d
A      |  340  | +0.92%      |  61%      | 2.6   | 5.1d
B      |  520  | +0.31%      |  53%      | 1.4   | 4.5d
C      |  260  | -0.15%      |  46%      | 0.9   | 4.2d (filtered out)

검증:
  Spearman(tier_rank, mean_return) > 0.95  → 합격
  S vs A gap > 0.5%                        → S-tier가 진정 의미 있음
  C tier가 reject 되어 실거래 0            → tier filter 작동
```

### 8.2 Regime별 성과 (Full 실험)

```
Regime        | Trades | Sharpe | MDD  | Win Rate | Top Action
strong_bull   | 18     | 2.4    | 3%   | 78%      | ADD_TO_WINNER (12)
bull          | 35     | 1.9    | 5%   | 66%      | ADD_NEW (28)
neutral       | 42     | 1.3    | 6%   | 60%      | ADD_NEW (30) + TRIM (5)
caution       | 22     | 0.7    | 7%   | 50%      | TRIM (8) + EXIT (10)
bear          | 0      | n/a    | 0%   | n/a      | NO_ACTION (cash)

검증:
  bear regime trade count == 0           → conviction-or-cash 원칙
  caution regime exit/trim 비중 ≥ 50%    → 리스크 감지
  strong_bull → bull → neutral Sharpe 감소 단조 → regime 의미
```

### 8.3 Action 분포 (Full 실험)

```
ACTION         | Count | % of total
ADD_NEW        | 78    | 38%
ADD_TO_WINNER  | 25    | 12%
KEEP           | 67    | 33%
TRIM           | 14    |  7%
EXIT           | 12    |  6%
ROTATE         |  6    |  3%
NO_ACTION      |  3    |  1%

검증:
  ADD_TO_WINNER가 ADD_NEW의 1/3 이상     → pyramid 활성
  EXIT 중 risk_exit / time_based 비율 > 1 → ExitThesis 작동
  ROTATE > 0 but ≤ max_rotations_per_month → rotation 적정
```

## 12. 위험 관리 — Ablation 결과가 기대와 다를 때

### 12.1 정책이 합격 기준 미달 시

```
대응:
  1. 합격 기준이 너무 공격적이었나? (재검토)
  2. 임계값이 잘못 도출됐나? (calibration 재검증)
  3. 정책이 실제로 효과 없는가? (paper 보류)
  4. 다른 정책과 충돌하는가? (단독 ablation 재실행)
```

### 12.2 Full이 V3.2.1보다 나쁠 때

```
가능한 원인:
  1. 정책 간 부정적 상호작용 (rotation × pyramid 등)
  2. 임계값 over-fit
  3. OOS 1년 표본의 특수성 (예: 2025-2026 변동성)

대응:
  1. 단독 ablation에서 통과한 정책만 "축소 Full"로 재실행
  2. Walk-forward로 표본 변동성 확인
  3. 일부 정책 보류, 핵심 (Conditional Veto + Allocation + Pyramid)만 promote
```

### 12.3 합격이지만 paper 결과 불일치 시

```
원인:
  - Backtest cost model과 실제 슬리피지 괴리
  - PaperBroker 시뮬과 실거래 차이
  - Universe rebalancing timing 차이

대응:
  - Execution Quality Monitor 데이터로 cost_model 재calibrate
  - Backtest를 paper 결과로 보정 후 ablation 재실행
```
